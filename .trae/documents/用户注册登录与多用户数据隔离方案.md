# 用户注册 / 登录与多用户数据隔离方案

## Context

现在整个系统是单用户模式：错题本、学情统计、学习报告全部存在全局 JSON 里，历史对话存在浏览器全局 localStorage 里，没有任何身份概念。需求是让学生可以自己注册账号、设置密码，每个账号拥有独立的错题、学情和对话；今天登录过的账号，明天再登录（包括后端重启后）内容仍然保留。

已确认的决策：
- 预置测试账号 `text / 12345`，首次启动自动创建，现有错题与学情归到该账号。
- 历史对话继续放浏览器 localStorage，但 key 按账号隔离；`text` 首次登录时把旧的全局会话迁移给它。
- 所有 `/api/**` 除注册、登录外都要求登录；前端未登录显示登录/注册页。
- 继续遵守项目约束：不用 MySQL，内存 + JSON 文件持久化；不引入 Spring Security / JWT 等新依赖。

## 总体设计

- **认证**：用户名 + 密码注册/登录。密码用 JDK 自带 `PBKDF2WithHmacSHA256` + 随机盐哈希后存 `data/users.json`，不存明文。
- **会话**：登录成功返回随机 token（`Authorization: Bearer <token>`）。token 存 `data/sessions.json`，有效期 30 天，后端重启后仍有效；退出时删除。
- **鉴权**：自定义 `AuthInterceptor` 校验 token，把 `userId` 和 token 写入 request attribute；注册/登录接口放行，OPTIONS 预检放行。控制器通过 `@RequestAttribute("userId")` 取当前用户。
- **数据隔离**：
  - 错题记录增加 `userId` 字段，所有查询/修改按用户过滤。
  - 学情统计改为 `Map<userId, UserState>`，`data/weakness.json` 升级为 `{ "users": { ... } }`，兼容旧的单用户结构。
  - 旧全局数据先标记为 `legacy`，启动迁移器把 `legacy` 合并给最早创建的账号（首次启动即 `text`）。
  - 前端会话 key 改为 `mathbuddy.sessions.v1:<userId>`。
- **初始化顺序**：三个 Store 的 `@PostConstruct` 先加载各自 JSON；`ApplicationRunner` 再创建 `text` 并把 `legacy` 数据划归给它，避免启动早期互相抢跑。

## 后端改动

### 新增

1. `service/UserStore.java`
   - `record User(String id, String username, String salt, String hash, long createdAt)`。
   - `record Session(String token, String userId, long expiresAt)`。
   - `data/users.json`、`data/sessions.json`；`@PostConstruct` 加载并清理过期 token。
   - `register(username, password)`：校验用户名 2–20 字、密码 5–32 字、用户名不重复（忽略大小写）；PBKDF2 120000 次、16 字节盐、Base64 存盐与哈希。
   - `login(username, password)`：`MessageDigest.isEqual` 比对；成功后生成 UUID token，30 天过期。
   - `validate(token)`、`logout(token)`、`findById(userId)`、`firstUser()`。
   - 所有写文件加锁，先写 `.tmp` 再 `ATOMIC_MOVE`，避免并发/崩溃写坏 JSON。
2. `controller/AuthController.java`（`/api/auth`）
   - `POST /register`、`POST /login`：返回 `{ token, user: { id, username } }`；用户名重复或密码错误返回 400 + `{ error }`。
   - `GET /me`：返回当前用户；`POST /logout`：删除当前 token。
   - `/me`、`/logout` 走拦截器；`/register`、`/login` 放行。
3. `config/AuthInterceptor.java`
   - 读取 Bearer token；无效返回 401 + UTF-8 JSON `{ "error": "请先登录" }`。
   - `OPTIONS` 直接放行（跨域预检）。
   - 成功时 `request.setAttribute("userId", ...)`、`setAttribute("authToken", ...)`。
4. `config/WebConfig.java`
   - 注册拦截器：`addPathPatterns("/api/**")`，排除 `/api/auth/register`、`/api/auth/login`。
5. `config/DataMigrationRunner.java`（`ApplicationRunner`）
   - 若没有任何用户：创建 `text / 12345`。
   - 取最早创建的账号；若存在 `legacy` 数据，调用 `MistakeBook.claimLegacy(userId)` 与 `WeaknessTracker.claimLegacy(userId)`。

### 修改

6. `service/MistakeBook.java`
   - `Mistake` 增加 `String userId`（旧 JSON 缺字段会反序列化为 `null`，加载时归一为 `"legacy"` 并回写）。
   - `add/list/find/setMastered/bumpReview/remove/summary` 全部增加 `userId` 参数；`find` 归属不符返回 `null`；去重只在同一用户内比较。
   - `claimLegacy(userId)`：把 `legacy` 记录改归该用户，保存。
   - `save()` 加锁 + 临时文件原子替换。
7. `service/WeaknessTracker.java`
   - 内部改为 `Map<String, UserState>`（每用户持有 counter / dailyCounter / quizAnswered / quizCorrect）。
   - `record/recordQuiz/mastery/trend/snapshot/topPoint` 增加 `userId`；`points()` 保持全局。
   - 加载时 `readTree` 判断是否有 `users`：有则读新结构；否则按旧单用户结构读入并放到 `legacy`。未知字段不会被静默覆盖。
   - `claimLegacy(userId)`：把 `legacy` 的各计数**求和合并**进目标用户，避免覆盖。
   - `save()` 加锁 + 原子替换。
8. `controller/ChatController.java`
   - 涉及用户数据的方法增加 `@RequestAttribute("userId") String userId`：
     - `/chat`：`weaknessTracker.record(userId, question)`、`mistakeBook.add(userId, ...)`。
     - `/stats`、`/mistakes`、`/mistakes/{id}` 的 PATCH/DELETE、`/retry`、`/ask`、`/recommend`、`/mindmap`（默认知识点取该用户 topPoint）。
   - `/variant`、`/upload`、`/explain` 不读写用户数据，但仍受登录拦截保护。
   - `retry/ask` 使用 `mistakeBook.find(userId, id)`，防止访问别人的错题。
9. `controller/QuizController.java`
   - `Quiz` 增加 `userId`；`/quiz/submit` 校验题目归属。
   - `/mastery`、`/report` 按 userId 取数；判错收录改为 `mistakeBook.add(userId, ...)`、`weaknessTracker.recordQuiz(userId, ...)`。
   - `/points` 仍返回全局知识点列表。

## 前端改动

### 新增

10. `src/api.js`
    - `AUTH_KEY = 'mathbuddy.auth.v1'`；`loadAuth / saveAuth / clearAuth`。
    - `authHeaders()`：有 token 时返回 `{ Authorization: 'Bearer ...' }`。
    - `apiFetch(url, options)`：自动合并认证头；401 时清空登录态并派发 `mathbuddy:unauthorized` 事件。
    - `notifyUnauthorized()`：供 SSE 的 `onopen` 在 401 时调用。
11. `src/components/LoginView.vue`
    - 居中白色卡片，登录 / 注册两个 tab，字段为用户名、密码；展示演示账号 `text / 12345`。
    - 注册成功直接进入系统；错误信息来自后端。
    - 使用原生 `fetch` 调 `/api/auth/login|register`，避免 401 事件干扰登录页。

### 修改

12. `src/App.vue`
    - 新增 `authState: checking | guest | ready`、`currentUser`。
    - `onMounted`：读取本地 token；无 token → `guest`；有 token → 请求 `/api/auth/me` 校验，成功则置 `ready` 并加载学情/会话，失败清 token → `guest`。
    - 模板：`checking` 显示加载态；`guest` 显示 `LoginView`；`ready` 显示现有三栏界面。避免面板在未登录时提前发请求。
    - 左栏品牌卡增加“当前账号 username + 退出”行。
    - `onAuthSuccess`：保存 token/user、重置聊天、`loadStats()`、读取该用户会话；`text` 首次登录时把旧 `mathbuddy.sessions.v1` 迁移到新 key 并删除旧 key。
    - `logout()`：先保存当前会话，再调用 `/api/auth/logout`（失败也继续），清 token、清内存状态、回到 `guest`。
    - 监听 `mathbuddy:unauthorized` → 回到登录页并提示登录过期。
    - 会话读写函数由固定 `STORAGE_KEY` 改为按当前用户动态 key。
    - 所有请求补认证头：`loadStats` 的 fetch、`/api/upload`、`streamFrom` 与 `/api/mindmap` 的 `fetchEventSource.headers`。
13. 面板组件
    - `MistakeBookPanel.vue`、`QuizPanel.vue`、`ReportPanel.vue`、`MindMapPanel.vue`：普通请求改用 `apiFetch`；`fetchEventSource` 的 headers 增加 `...authHeaders()`，`onopen` 遇到 401 调用 `notifyUnauthorized()`。

## 实施顺序

1. 后端认证底座：`UserStore`、`AuthController`、`AuthInterceptor`、`WebConfig`。
2. 数据隔离：`MistakeBook`、`WeaknessTracker` 加 userId / 结构迁移 / 原子保存。
3. 控制器接线：`ChatController`、`QuizController` 全部用户相关接口传 userId。
4. 启动迁移：`DataMigrationRunner` 创建 `text / 12345` 并划归旧数据。
5. 前端：`api.js`、`LoginView`、`App.vue` 登录门禁与账号信息。
6. 前端面板与 SSE 补认证头、会话 key 按账号隔离。
7. 构建与端到端验证。

## 验证

- 启动后端（IDE 中重启）：`data/users.json` 自动出现 `text`，`password` 不落明文；`mistakes.json` 旧记录带上 `text` 的 userId；`weakness.json` 变为 `{ users: ... }`。
- 接口：
  - 无 token 请求 `/api/mistakes` → 401。
  - `POST /api/auth/login`（text/12345）→ 返回 token；带 token 请求 `/api/mistakes` → 约 10 条旧错题；`/api/stats` → 旧学情。
  - 注册 `u2` → 错题为空；用 `u2` 的 token PATCH `text` 的错题 → 404。
  - `u2` 提问与自测只增加 `u2` 的统计，`text` 不受影响。
  - 重启后端后原 token 请求 `/api/auth/me` 仍成功。
- 前端：`npm run build` 通过；浏览器验证登录页 → `text` 登录看到旧数据 → 退出 → 注册新账号数据为空 → 刷新/重启后重登数据仍在；`text` 登录后旧历史对话迁移到账号 key。
- 注意：本地 `mvn` 不在 PATH，后端编译与启动需在 IDE 中完成。

## 风险与处理

- **Jackson 兼容**：`Mistake.userId` 用 `String`，缺失即 `null` 后归一为 `legacy`；`WeaknessTracker` 必须先 `readTree` 判结构，不能直接按新结构反序列化。
- **并发写文件**：两个 Store 的 `save()` 均加锁并原子替换。
- **SSE 鉴权**：`fetchEventSource` 支持自定义 header；所有 SSE 调用都要带 `Authorization`，401 时触发全局登出。
- **越权**：错题的新增、查询、修改、删除、变式、AI答疑，以及自测提交都要校验 userId。
- **登录门禁时序**：`authState === 'checking'` 时不要挂载主界面和面板，避免竞态请求。
